## Commit Body

The v1 workflow used `actions/checkout@v4` with the `repository:` field to fetch the governance repo into a sibling path. That step failed in production with `fatal: repository ... not found` because GitHub's default GITHUB_TOKEN cannot read private repositories across the actions/checkout boundary even within the same org (a security policy introduced in 2023). The real run of v1 on `axiomaticworld/axi-registry` confirmed the failure.

Replace the sibling `actions/checkout` step with a `git clone` against the public git endpoint using the `x-access-token:${GITHUB_TOKEN}` credential prefix, which succeeds because the runner's GITHUB_TOKEN has the workflow scope. The downstream steps (pnpm install, git-hooks:test, install, verify) are unchanged. AXI_HOOKS_SELF_ONLY=1 keeps the audit scoped to the owning repository; the gate still rejects any axiom-owned commit that bypasses the local hook.
