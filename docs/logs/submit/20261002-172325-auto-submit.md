fix(axi-todo): upsertTask writes source + imported_at with sticky ON CONFLICT semantics

## Commit Body

upsertTask is the single INSERT/UPSERT path for the tasks row (called from addTask, updateTask, claimNextTask, completeTask, etc.). It now writes the two provenance columns added in 003_task_provenance.sql:

- source: text NOT NULL DEFAULT 'native' — bound as task.source ?? 'native'
- imported_at: timestamptz — bound as task.importedAt ?? null

Sticky semantics: the INSERT column list includes both new columns, but the ON CONFLICT DO UPDATE SET clause deliberately does NOT list source or imported_at. This preserves the original import timestamp across subsequent updateTask / claimNextTask / completeTask calls — exactly the M2 importer contract (source + importedAt are written once at import time, not on every subsequent write).

The payload column on conflict uses:
  payload = excluded.payload || jsonb_strip_nulls(jsonb_build_object('source', tasks.source, 'importedAt', tasks.imported_at))

This keeps the JSON-compatibility surface in sync: any client that reads payload directly (e.g. the Swift AxiTodoStore bridge reading JSON side) still sees the source / importedAt keys after every update, because the reverse-sync writes the *current* (sticky) PG columns back into payload. The reconciler therefore sees consistent provenance across both reads paths.
