## Commit Body

Closes M5-OUT-3 (carried from M5 outOfScopeButFlagged): when a JSON-only
Swift install runs without the importer, PG data stays orphaned. This
tool is the missing half of M2's dual-store architecture.

Surface:
  node bin/axi-todo-sync-pg-to-json.mjs                              # dry-run (default)
  node bin/axi-todo-sync-pg-to-json.mjs --apply --confirm-apply
  node bin/axi-todo-sync-pg-to-json.mjs --apply --confirm-apply \
    --only-collections=tasks,completion_summaries

Strict rules (each is a real failure mode, not a stylistic preference):
- JSON is canonical — rows already present in JSON are NEVER silently
  overwritten, regardless of which side has the newer updatedAt. Drift
  is surfaced through summary.warnings so operators can audit divergence
  without the tool clobbering local state.
- Owner-gated — dry-run by default; --apply requires --confirm-apply
  (double-flag confirmation, matching the M5.S5 pattern). --apply without
  --confirm-apply exits 1 with a stderr message; there is no silent
  fallback. The owner-gate check runs BEFORE any pg.Client connect so a
  typo never burns a network round-trip.
- Reentrant — .synced-pg-to-json-ids.json (parallel to
  .imported-pg-ids.json) records which PG ids have been merged into JSON;
  re-runs skip them. Acts as a second-line guard against re-adding a row
  that was previously synced and then deleted from JSON.
- No implicit DATABASE_URL default — same env-var contract as the
  importer and the migrator (M2.S4 lesson).
- Pre-sync backup — before mutating JSON the tool writes the current
  state to <home>/.m1-snapshot/m6-audit/pre-sync-<ISO>.json so the
  operator has a recoverable point.
- Provenance — new tasks get source='import-postgres' + importedAt set,
  matching the M2 importer convention. Non-task collections get the same
  source/importedAt fields on the JSON record.

PG schema coverage (10 collections): tasks (via payload jsonb), taskCharters,
planningRecords, taskRuns, taskEvents, failureAnalyses, auditReviews,
userPreferences, completionSummaries, memoryCards. The tasks collection flows
through createTask() so the new task gets the full normalization the rest of
the ledger expects; other collections are converted snake_case → camelCase
and added directly.

runSync() is the testable orchestrator (same shape as runImport() in the
existing tool). It accepts pgState directly so they do not need a live pg.Client
to exercise the merge + backup + provenance paths.
