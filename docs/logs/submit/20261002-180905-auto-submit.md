## Commit Body

M4 added source + imported_at to the JSON-side task shape and mirrored them onto the PG tasks table via migrations/003_task_provenance.sql + lib/postgres-store.mjs upsertTask with sticky ON CONFLICT semantics. The four planning-memory tables the ledger carries alongside tasks — completion_summaries, failure_analyses, planning_records, memory_cards — had no equivalent PG columns, so their JSON-side provenance (visible to the Swift bridge through payload) was trapped inside jsonb, not queryable / not indexable.

This migration extends the mirror in a single file:

- For each of the 4 target tables: ADD COLUMN source text NOT NULL DEFAULT 'native' + ADD COLUMN imported_at timestamptz + backfill from payload (COALESCE + NULLIF empty strings) + reverse-sync into payload (jsonb_strip_nulls(jsonb_build_object('source', source, 'importedAt', imported_at::text))) + CREATE INDEX <table>_source_idx ON <table> (source)
- 20 statements total (4 tables × 5 ops)
- Idempotent on re-run (every ALTER is IF NOT EXISTS, every UPDATE uses COALESCE / NULLIF)

The lib/postgres-store.mjs changes (separate commit) turn insertCompletionSummary / insertFailureAnalysis / insertMemoryCard into INSERT ... ON CONFLICT (id) DO UPDATE with sticky semantics: source / imported_at written on first INSERT, deliberately omitted from the SET list so re-upserts preserve the original import marker.
