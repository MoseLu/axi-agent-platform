## Commit Summary

fix(axi-todo): recordCompletionSummary / recordFailureAnalysis drop misleading task arg

## Commit Body

Both public methods previously wrapped the inner helper call as insertCompletionSummary({ id: record.taskId }, record) / insertFailureAnalysis(task || { id: input.taskId }, record). Readers of the call site would assume the helpers received a task object and therefore the completion_summaries.id / failure_analyses.id columns would derive from task.id — but the helpers' factory functions actually read input.id || crypto.randomUUID() for the PK and input.taskId for the FK, so the misleading object never affected runtime behaviour (the PK is a fresh UUID, the FK is input.taskId). M2 ledger outOfScopeButFlagged had documented this as a runtime bug; it was actually a misdiagnosis.

This commit makes the contract explicit: pass null to insertCompletionSummary / insertFailureAnalysis and let the factories fall back through taskFallback = task || {} so they tolerate null. The factory fallbacks (task.id, task.lastRunId, task.status, task.summary, task.verification, task.error) still serve the legitimate caller in completeTask (lib/postgres-store.mjs:210) which passes a real task object.

Ledger note: M3 outOfScopeButFlagged records this misdiagnosis to prevent future readers from re-deriving the same wrong conclusion.
