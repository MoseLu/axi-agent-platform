fix(axi-todo): require explicit DATABASE_URL for PG migrator

## Commit Body

Previously `bin/axi-todo-migrate-postgres.mjs` silently fell back to
`postgresql:///axi_todo` when neither `DATABASE_URL` nor
`AXI_TODO_DATABASE_URL` was set. That default was inherited from the
implicit `DEFAULT_POSTGRES_DATABASE_URL` constant in
`lib/postgres-store.mjs` and produced real "looks connected, actually
empty DB" incidents when operators forgot to set the env var (see M2
ledger `outOfScopeButFlagged`).

The migrator now exits 1 with a clear stderr message when both env vars
are missing:

  axi-todo-migrate-postgres: DATABASE_URL (or AXI_TODO_DATABASE_URL)
  is required. Refusing to silently fall back to an implicit database
  URL.

The default is not removed from `lib/postgres-store.mjs` because
`createStoreFromEnv` still legitimately needs it as a last-resort
fallback for backwards compatibility. The migrator and importer are the
two entry points where the silent fallback was actively dangerous, so
both now require an explicit URL.

Tested: `unset DATABASE_URL AXI_TODO_DATABASE_URL && node bin/axi-todo-migrate-postgres.mjs` exits 1 with the new message; node --test 123/123 still pass.
Not-tested: live psql migration against a real DB.
Confidence: high
Scope-risk: low — only changes behaviour when env vars are missing (previously silent, now loud).
Directive: ship; breaking the silent fallback is the point.
