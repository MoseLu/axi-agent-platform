## Commit Body

M4 added source / imported_at to the PG tasks table; M6 mirrored that onto
the four auxiliary collections (completion_summaries, failure_analyses,
planning_records, memory_cards). M6 newFindings surfaced two more PG tables
that ALSO carry JSON-side provenance but had no queryable, indexable PG
column: audit_reviews (one row per audit decision) and task_events (one
row per state-transition event: claimed, completed, audit_waiting,
retry_scheduled, ...). M7 closes that gap.

Pattern mirrors 003_task_provenance.sql and 004_collection_provenance.sql
exactly: ADD COLUMN IF NOT EXISTS source text NOT NULL DEFAULT 'native' +
ADD COLUMN IF NOT EXISTS imported_at timestamptz + backfill UPDATE with
COALESCE / NULLIF for payload-side fallback + reverse-sync UPDATE that
writes source / importedAt back into payload so JSON-side readers keep
seeing the same keys + CREATE INDEX IF NOT EXISTS for source-cardinality
queries. 10 statements total (2 tables x 5 ops). Idempotent: every
ALTER uses IF NOT EXISTS, every UPDATE uses COALESCE / NULLIF.

Sticky provenance contract: source / imported_at are set on the first INSERT
and DELIBERATELY omitted from the ON CONFLICT DO UPDATE SET in
lib/postgres-store.mjs. Re-upserts preserve the original import marker;
the payload jsonb column is reverse-synced from the canonical column
values on every conflict.
