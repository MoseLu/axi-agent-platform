## Commit Summary

fix(axi-todo): recordAuditReview wraps audit insert + status flip in single transaction

## Commit Body

Previously the audit_reviews INSERT and the status flip + audit_waiting history event ran in two separate implicit transactions via pool.query + this.updateTask, leaving a window where an audit insert succeeded but the status update or history event failed and left the system in a half-applied state.

Now both run inside one withClient: audit_reviews INSERT first, then on a non-pass verdict we getTaskForUpdate(client), mutate status to awaiting_audit, upsertTask via the same client, and write the audit_waiting task_events row. On any failure the entire withClient rolls back, restoring the previous behaviour of completeTask (which already used this idiom).

The status-flip path no longer calls this.updateTask (which would have started its own second transaction), matching the existing completeTask pattern.
